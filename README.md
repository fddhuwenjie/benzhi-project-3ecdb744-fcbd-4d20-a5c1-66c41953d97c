# shelter-drill-gate

`shelter-drill-gate` 是面向公共应急避难场所管理团队的演练就绪认证工作台。它把演练基线冻结、启用证据、现场检查点记录、规则判定、缺陷整改复测、独立复核和只读就绪档案收束在一条可审计的状态流程中。

服务由 Go 直接提供原生 HTML、CSS、JavaScript 页面和同源 JSON API，无需 Node 构建链。业务数据保存在本地 SQLite；每次写操作使用 `request_id` 保证重试幂等，使用 `expected_revision` 防止并发覆盖，并在同一事务中追加 SHA-256 摘要链事件。送审时会固定不可变快照，批准后生成可复算摘要的只读档案。

启用门禁按疏散路线、通信设备、无障碍设施和人员到位分别保存采集时间、有效截止时间与 SHA-256 内容摘要；登记和启动时都会核验完整性、时间关系、重复摘要及当前有效期。现场记录成功后生成不可覆盖的逐项判定回执，记录实测值、冻结阈值、偏差、规则代码和规则版本，并把同次产生的整改项关联到该回执。

## 状态流程

正常流程为：`draft` → `baseline_frozen` → `in_progress` → `remediation`（存在规则问题时）→ `pending_review` → `certified`。

协调员必须依次完成检查点记录。人数不足、耗时超限、通信失败或无障碍失败会按冻结的规则版本自动生成整改项；问题只有在原因、措施、责任人、复测计划和通过原规则的定向复测证据齐全后才能关闭。待复测计划可在复测前附理由调整，详情按严重度和到期风险组织待办，并保留所有计划版本。独立复核员不能与协调员相同；复核请求必须完整提交由送审快照生成的基线、启用证据、检查点判定、整改闭环和审计链清单。退回项会定向关联原检查点或证据类别，批准档案包含可复算的清单摘要与通过数量。

## 构建

```sh
go build ./cmd/shelterd
```

## 运行

```sh
go run ./cmd/shelterd -addr=127.0.0.1:19081 -db=shelter-drill-gate.db
```

浏览器访问 `http://127.0.0.1:19081`。未传 `-addr` 时，服务优先读取 `PORT` 并监听 `127.0.0.1:<PORT>`；未设置 `PORT` 时默认使用 `127.0.0.1:19081`。服务拒绝非回环监听地址。

## 测试

运行全部单元与适配层测试：

```sh
go test ./...
```

运行有界真实 HTTP 自检：

```sh
go run ./cmd/shelterd -self-check -addr=127.0.0.1:19081
```

自检使用临时 SQLite 数据库和真实回环 HTTP 服务，完成一次产生严重问题、登记整改、定向复测、独立批准和档案摘要验证的完整流程，成功后主动退出。

## 主要目录

- `cmd/shelterd`：监听配置、服务生命周期和真实 HTTP 自检。
- `internal/domain`：实体、状态机、字段约束和确定性规则。
- `internal/audit`：规范 JSON、事件摘要链、档案生成与验证。
- `internal/store`：SQLite 迁移、事务、幂等结果、快照和只追加事件。
- `internal/workflow`：完整业务用例、并发控制和查询视图。
- `internal/web`：单页工作台、静态资源和同源 JSON handler。
